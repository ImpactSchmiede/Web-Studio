# HF-001: Testsuite unter Linux rot (Leck-Prüfung hing am Benutzernamen)

**Datum:** 2026-10-19
**Kontext:** Abnahme T-003 durch den Co-PO im frischen Klon unter Linux; Auftrag T-004 (B-001)
**Commit:** bf4dc6b
**Tests:** Windows 386 bestanden, 1 übersprungen (Datei-Symlink braucht Sonderrecht, Junction-Test deckt ab); Linux (WSL, Node 22.20) 387/387 als normaler Benutzer und als root
**Plattform:** E2E unter Windows 11 (Node 24.19) und Linux (WSL2 Ubuntu, Node 22.20); Paket-SHA-256 auf beiden `d05bb94d8794725534b5a95e0740eec19cc287bcedd4e94b068de7146a18c299`

**Problem:** `npm test` war nur auf dem Rechner grün, auf dem das Profil-PDF entstanden ist. Unter Linux schlug `pruefePdf rot bei: Benutzername in Name mit \#20` fehl. Die QA fand danach mehr: Bei Benutzern wie `root` (Docker), `info`, `page` oder `enrico` meldete die Leck-Prüfung Fehlalarme, und `npm run build` brach ab.
**Recherche:** „PDF name object #20 escape“. Laut Adobe-Doku zu COS-Objekten (Acrobat SDK, „Working with Cos Objects“) steht `#20` in PDF-Namen für ein Leerzeichen; die Kodierung entsteht also nur bei Namen mit Leerzeichen. Die Norm (ISO 32000-1 §7.3.5) habe ich nicht im Original gelesen.
**RCA:** `pruefePdf` hat die Suchmuster für Benutzer- und Rechnername aus der Umgebung gelesen (`os.userInfo`, `os.hostname`). Der Testfall setzte aber fest `AI#20User` ein und passte damit nur zum Windows-Benutzer „AI User“. Dazu kam die Suche als Teilzeichenkette: Sie traf Strukturnamen (`/Root`, `/Info`) und Inhalte wie den Titel „Enrico Falk – Profil“ oder `https://enricofalk.de/`.
**Evidenz:** `docs/batches/B-001/evidenz/T-004/`
- `linux-lauf.txt`: Stand 7270951 unter Linux 368 von 369, genau der gemeldete Test; nach dem Fix 387/387 als normaler Benutzer und als root.
- `test-rot-vor-fix.txt`: Nachstellung unter Windows mit gemockter Linux-Umgebung, 8 rot.
- `qa/`: QA-Läufe mit fremden Benutzer- und Rechnernamen, Zeitzonen und Locale.

**Fix:**
- `pruefePdf(buf, { kennungen })` nimmt Benutzer- und Rechnername optional entgegen; ohne Angabe gilt weiter die Umgebung. Build, `npm run check` und `paket:pruefen` bleiben damit scharf.
- Kennungen ab 4 Zeichen werden nur als ganzes Wort gesucht.
- Nicht gesucht wird eine Schreibweise, die einem PDF-Strukturnamen gleicht oder als ganzes Wort im erwarteten Titel oder Autor bzw. in einem erlaubten `https:`/`mailto:`-Verweis steht. Das gilt nur, wenn eine Erwartung übergeben wird; die Prüfung nennt die Kennung dann als Hinweis (`npm run check`: „Hinweis:“).
- Die Tests verwenden feste Kennungen mit und ohne Leerzeichen.
- Paket- und Profil-Tests suchen nur feste Pfadmuster.

**Grenze:** Geprüft wird nur der Name der prüfenden Maschine (siehe `docs/referenzen/pdf-chrome.md`).
**Rollback:** `git revert bf4dc6b`. Betroffen sind nur Prüfcode, Tests und Doku; Seite, PDF und Paket sind unverändert.
